01 — What is JavaScript?

What is JavaScript?

A high-level, interpreted scripting language used to create dynamic and interactive content on websites.

Common Uses
  • Frontend development (with HTML & CSS)
  • Backend development (using Node.js)
  • Game development
  • Mobile & Desktop app development
  • AI, Automation, and IoT
Key fact
  • It converts JavaScript code into machine code so the computer can understand and execute it quickly

02 — How JavaScript Runs + JRE

How JavaScript Runs & JavaScript Runtime Environment

Understanding the engine, execution model, and runtime is critical for interviews.

How JavaScript Runs — 4 Steps

1. You write JS code
→
2. JS Engine reads it
→
3. Converts to machine code
→
4. CPU executes

JavaScript is single-threaded — how can it handle multiple requests? frequently asked

  • JS is single-threaded — has only one Call Stack and can execute only one piece of code at a time
  • However, JS can still handle multiple requests because it gets help from the Browser (or Node.js) and the Event Loop
  • When JS encounters async operations like: API calls (fetch()), Timers (setTimeout()), File operations, Database queries — it does NOT execute them itself
  • Instead, it sends them to the Browser's Web APIs (or Node.js APIs)
  • While those run in the background, JavaScript continues executing the next lines of code
  • When the async task finishes, its callback is placed in a queue
  • The Event Loop checks whether the Call Stack is empty → if yes, moves the callback to the Call Stack for execution

JavaScript Engine

  • The JavaScript Engine is a program (written in C++) that reads and executes JavaScript code

04 — Variables

Variables: var · let · const

Three keywords to declare variables — each with different scoping rules and behaviour.

KeywordValue ChangedRe-declared
var✅ Yes✅ Yes
let✅ Yes❌ No
const❌ No❌ No
javascript — var · let · const examples
var name = "John";
name = "Doe";          // ✅ Changed
var name = "Jane";     // ✅ Re-declared

let age = 25;
age = 30;              // ✅ Changed
let age = 35;          // ❌ Error: Cannot re-declare

const pi = 3.14;
pi = 3.1415;           // ❌ Error: Cannot change
const pi = 3.1416;    // ❌ Error: Cannot re-declare

Why ES6 introduced let and const

  • var is function-scoped (not block-scoped) — can be accessed outside the block where declared
  • var allows re-declaration and behaves confusingly due to hoisting — leads to unexpected bugs
  • let is block-scoped and used for variables whose values can change
  • const is also block-scoped but its value cannot be reassigned — makes code safer and more predictable

Are let and const Hoisted?

Many people think let and const are NOT hoisted — this is wrong must know
javascript
let a = 10;
const b = 20;
// Both are hoisted.
// Difference:
// var   → stored in window object (initialized as undefined)
// let   → separate memory space (stays in TDZ until declaration)
// const → separate memory space (stays in TDZ until declaration)

Temporal Dead Zone (TDZ)

The time between variable hoisting and variable initialization frequently asked
javascript
console.log(a);   // Output: ReferenceError
let a = 10;
// Because: a is hoisted, but not initialized → TDZ

// But this works:
let a;
console.log(a);   // undefined — declared but no value assigned
05 — Scope & Lexical Environment

Scope, Lexical Environment, Block & Shadowing

Scope determines where a variable can be accessed in the code.

Global Scope
  • Variable can be used anywhere in the program
Function Scope
  • Variable declared inside a function can only be used inside that function
Block Scope
  • let or const inside { } can only be used inside that block
💡 In real-world projects, scope helps prevent bugs, avoids variable conflicts, and keeps code secure and maintainable.
javascript — scope examples (exact from your notes)
// global scope
let age = 30;
function show_age(){
  console.log(age)
}
show_age()

// Function Scope
function age(){
  let ages = 20;
  console.log(ages)
}
age();

// block scope
function show_age(){
  if (10 < 20){
    let age = 30;
    console.log(age)
  }
}
show_age()

Lexical Environment

Lexical Environment = Local Memory + Reference to Parent Lexical Environment
javascript
function a() {
  var x = 10;
  function b() {
    console.log(x);  // b() is lexically inside a()
  }
  b();
}
// b() is written inside a()
// So b() is lexically inside a()
// Lexical means "where the function is physically written"

Block and Block Scope

javascript
// A block is simply: { // block }
if (true) {
  console.log("Hello");
  console.log("Balaji");
}

// Variables declared with let and const are accessible ONLY inside the block
{
  let a = 10;
  const b = 20;
}
console.log(a); // ReferenceError
console.log(b); // ReferenceError

Shadowing

Declaring a variable in an inner scope with the same name as an outer scope variable
javascript
let a = 100;
{
  let a = 10;
  console.log(a);  // 10
}
console.log(a);     // 100
06 — Hoisting & Global Execution Context

Hoisting, GEC & Global Object

Hoisting is JavaScript's behavior of allocating memory for variables and functions before the code starts executing.

Global Execution Context (GEC) — 2 Phases most asked
  • Whenever a JavaScript program runs, a Global Execution Context (GEC) is created
  • Phase 1: Memory Creation Phase — Before executing any line, JavaScript scans the entire file
  • Phase 2: Code Execution Phase — JavaScript executes line by line

Phase 1 — Memory Creation Phase

javascript — memory creation example
var x = 10;
function greet() {
  console.log("Hello");
}
// Memory created:
// x       : undefined
// greet   : entire function code

Hoisting Examples

javascript — all hoisting cases from your notes
// WHY THIS WORKS — var hoisted as undefined
console.log(x);    // Output: undefined
var x = 10;
// Memory Phase: x : undefined
// Execution: console.log(x) prints undefined

// undefined vs not defined
// 1. undefined
console.log(x);    // Output: undefined
var x = 10;
// Reason: x exists in memory, but value not assigned yet

// 2. not defined
console.log(x);    // Output: ReferenceError: x is not defined
// Reason: x does not exist in memory

// FUNCTION HOISTING — entire function stored in memory
greet();
function greet() {
  console.log("Hello");
}
// Output: Hello
// Why? Memory Phase: greet : entire function code

// FUNCTION EXPRESSION HOISTING
sayHi();
var sayHi = function() {
  console.log("Hi");
};
// Output: TypeError: sayHi is not a function

// ARROW FUNCTION HOISTING
getName();
var getName = () => {
  console.log("Balaji");
};
// Output: TypeError: getName is not a function
// Arrow functions and function expressions behave like variables

Shortest JavaScript Program + Global Object

  • Shortest JS program = Empty file — even empty file creates: Global Execution Context (GEC), Global Object (window), this keyword
  • In browsers, the global object is window
  • At global level: console.log(this) → window; console.log(this === window) → true
  • Anything outside a function is in the global space: var a = 10; and function greet(){}

Error Types

SyntaxError
  • JS cannot understand the code because syntax is invalid
  • Example: let a = ;
ReferenceError
  • Accessing a variable that doesn't exist or is in TDZ
TypeError
  • Operation on a value that doesn't support it
javascript — let hoisting TDZ explained
// Case 1: ReferenceError — accessing in TDZ
console.log(a);
let a;
// let a is hoisted but not initialized
// Between start of scope and "let a" → TDZ
// Accessing it throws ReferenceError

// Case 2: undefined — declared first
let a;
console.log(a);  // undefined
// a is declared first → initialized with undefined

A loop is used to repeat a block of code multiple times — either a set number of times or while a condition is true.

13 — Closures

Closures

A Closure is a function bundled together with references to its lexical environment.

What is a Lexical Environment?
  • A Lexical Environment is the combination of: Local variables, Functions declared inside it, Reference to its outer (parent) lexical environment
  • Lexical means "where the function is physically written in the code"
javascript — classic closure example (your exact code)
function x() {
  var a = 7;
  function y() {
    console.log(a);
  }
  return y;
}
var z = x();
console.log(z);
z();

// Step 1: Call x()
//   var z = x();
//   Creates: a = 7, y = function
// Step 2: Return y
//   y() is not executed. The function y is returned. Now: z = y;
// Step 3: x() Finishes
//   x() execution ends. Normally a should be removed.
//   But JavaScript keeps 'a' because y() still needs it.
// Step 4: Call z()
//   z is actually y(). y() accesses a.
//   Output: 7

// Why Does Closure Work?
// JavaScript does NOT copy variables.
// Instead, it stores a REFERENCE to them.
javascript — closure with setTimeout
// Example 1: closure remembers i
function x(){
  let i = 2;
  setTimeout(()=>{
    console.log(i)
  }, 2000)
  console.log("hi!!!!")
}
x()
// Output: hi!!!! , 2

// Example 2: let in loop — creates new memory each iteration
function x(){
  for (let i = 1; i <= 5; i++){
    setTimeout(()=>{
      console.log(i)
    }, i*1000)
  }
  console.log("hi!!!!")
}
x()
// Output: hi!!!! , 1 ,2 , 3 , 4 , 5
// Every time it creates new memory because let is block-scoped
// But using var → it refers to same memory of 6

17 — Pure vs Impure Functions

Pure & Impure Functions

Core concept in functional programming — important for writing predictable, testable code.

Pure Function predictable
  • Always returns the same output for the same input
  • Does NOT change anything outside the function (no side effects)
javascript

}

  • Changes something outside the function
  • Or gives different outputs for the same inputs
javascript

  count++;  // changing outside variable
  return count;
}

console.log(increase());  // 2

JavaScript doesn't wait for long tasks to finish. It can run other code while waiting.

23 — Event Loop

JavaScript Event Loop

JavaScript is single-threaded — the event loop is what allows it to handle async operations without blocking.

5 Components must know
  • 1. Call Stack — where JavaScript executes code
  • 2. Web APIs — some operations take time: setTimeout(), setInterval(), fetch(), DOM Events, Geolocation — handled by browser Web APIs, NOT by JS engine
  • 3. Task Queue (Macrotask Queue) — when async operation finishes, callback placed here. Examples: setTimeout(), setInterval(), DOM Events
  • 4. Microtask Queue — Microtasks have higher priority than Task Queue. Examples: Promise .then(), .catch(), .finally(), queueMicrotask()
  • 5. Event Loop — continuously checks: Is Call Stack empty? → If yes, execute all Microtasks → Then execute one Task from Task Queue → Repeat forever
javascript — event loop step-by-step example
console.log("Start");
setTimeout(() => {
  console.log("Macro Task");
}, 0);
Promise.resolve().then(() => {
  console.log("Micro Task");
});
console.log("End");

// Step 1: console.log("Start")         → Prints: Start
// Step 2: setTimeout()                  → "Async task, Browser handle it" → Callback in Task Queue
// Step 3: Promise.resolve().then()      → "Promise callback" → Put in Microtask Queue
// Step 4: console.log("End")            → Prints: End
// Step 5: Call Stack empty → Event Loop checks Microtasks → Prints: Micro Task
// Step 6: Microtask Queue empty → Event Loop checks Task Queue → Prints: Macro Task

// Final Output:
// Start
// End
// Micro Task
// Macro Task

25 — Callback Hell & Inversion of Control

Callback Hell & Inversion of Control

Two key problems with callbacks that led to the invention of Promises.

Callback Hell (Pyramid of Doom)
javascript
register(function(){
  login()
})
// Hard to read, debug, manage errors
// Deeply nested callbacks = Pyramid of Doom
Inversion of Control
  • Means giving another function the responsibility to execute your callback
  • login is your function — you pass it to register()
  • Now register() decides: When to call login, Whether to call login, How many times
  • You no longer have control — this is Inversion of Control
⚠ To solve Callback Hell and Inversion of Control → we use Promises

  console.log("grandparent clicked ")

  console.log("parent clicked ")
}, true)

// false (default) → Bubbling
// true → Capturing

39 — Shallow vs Deep Copy

Shallow Copy & Deep Copy

Copy means creating another variable from an existing variable. There are 2 types.

1. Shallow Copy
  • Creates a new object, but nested objects are still shared with the original object
  • Changing nested data in copy affects the original
2. Deep Copy
  • Creates a completely independent copy of the object, including all nested objects
  • Changes don't affect the original
