01 — Foundations

What is JavaScript?

A high-level, interpreted scripting language used to create dynamic and interactive content on websites — the only language that runs natively in the browser.

Key Characteristics
  • High-level — abstracts away memory management; easy to write
  • Interpreted — executed line by line at runtime (no manual compilation)
  • Single-threaded — one task at a time using a single call stack
  • Dynamically typed — variable types are determined at runtime, not declared
  • Event-driven — responds to user actions, timers, and network responses

Common Uses

  • Frontend — dynamic UI with HTML & CSS (React, Vue, Angular)
  • Backend — server-side with Node.js
  • Mobile apps — React Native, Ionic
  • Desktop apps — Electron (VS Code is built with it)
  • Game development, AI/ML (TensorFlow.js), IoT
  • API integration, automation, browser extensions

JavaScript Engine

  • A JS engine reads and runs JavaScript code — converts it to machine code
  • Chrome / Node.js → V8
  • Firefox → SpiderMonkey
  • Safari → JavaScriptCore
  • Edge → Chakra (old) → now uses V8

Client-Side vs Server-Side

Client-Side (Frontend)
  • Runs in the user's browser
  • Handles UI, interactions, animations
  • Example: clicking a button shows a dropdown — JS handles it without contacting the server
Server-Side (Backend)
  • Runs on a remote server using Node.js
  • Handles data processing, database access, authentication
  • Example: login form → server checks password in database

02 — Variables

Variables: var, let, const

Three ways to declare variables in JavaScript — know the differences, scoping rules, and when to use each.

KeywordRe-assignableRe-declarableScopeHoisted
var✅ Yes✅ YesFunction scopeYes (as undefined)
let✅ Yes❌ NoBlock scopeYes (but not initialised — TDZ)
const❌ No❌ NoBlock scopeYes (but not initialised — TDZ)
javascript — var, let, const
// VAR — function-scoped, can be re-declared
var name = "John";
name = "Doe";         // ✅ Changed
var name = "Jane";    // ✅ Re-declared (problematic!)

// LET — block-scoped, cannot re-declare
let age = 25;
age = 30;             // ✅ Changed
// let age = 35;   → ❌ Error: Cannot re-declare

// CONST — block-scoped, cannot change
const PI = 3.14;
// PI = 3.1415;    → ❌ Error: Cannot assign to const
// BUT: const objects/arrays can be mutated (not re-assigned)
const user = { name: "Alice" };
user.name = "Bob";    // ✅ Allowed — mutating the object
// user = {};       → ❌ Error — re-assigning the variable
💡 Best practice: Always use const by default. Use let when you need to reassign. Never use var in modern JavaScript — it causes hoisting and scoping bugs.

04 — Scope

Scope

Scope determines where a variable can be accessed in your code. In real projects, scope prevents bugs and variable conflicts.

Global Scope
  • Variable declared outside any function or block
  • Accessible anywhere in the entire program
  • Too many globals = messy, collision-prone code
Function Scope
  • Variable declared inside a function
  • Only accessible within that function
  • Both var, let, const are function-scoped when declared inside
Block Scope
  • Variables declared with let/const inside { }
  • Only accessible inside that block
  • var does NOT have block scope — it leaks out
javascript — scope examples
// Global scope
let age = 30;
function showAge() { console.log(age); }  // ✅ accessible
showAge();

// Function scope
function myFunc() {
  let secret = "inside only";
  console.log(secret);               // ✅ works
}
// console.log(secret); → ❌ ReferenceError

// Block scope — let/const respect blocks
if (true) {
  let blockVar = "I am block-scoped";
  console.log(blockVar);             // ✅ works
}
// console.log(blockVar); → ❌ ReferenceError

// var LEAKS out of blocks (not block-scoped!)
if (true) {
  var leaked = "I leaked!";
}
console.log(leaked);                  // ✅ accessible — var bug!
Lexical Scope
  • A function's scope is determined by where it is defined, not where it is called
  • Inner functions can access variables from their outer (parent) scope
  • This is the foundation of closures
05 — Hoisting

Hoisting

JavaScript moves declarations to the top of their scope before executing code — during the memory creation phase.

javascript — hoisting behaviour
// var is hoisted and initialised with undefined
console.log(x);    // undefined (NOT error)
var x = 5;

// let / const are hoisted but NOT initialised (Temporal Dead Zone)
// console.log(y); → ❌ ReferenceError: Cannot access 'y' before init
let y = 10;

// Function DECLARATIONS are fully hoisted (can be called before defined)
sayHello();                          // ✅ works — "Hello!"
function sayHello() { console.log("Hello!"); }

// Function EXPRESSIONS are NOT fully hoisted
// greet();  → ❌ TypeError: greet is not a function
var greet = function() { console.log("Hi!"); };
⚠ Temporal Dead Zone (TDZ): The period between when let/const variables are hoisted and when they are initialised. Accessing them in TDZ throws a ReferenceError.
06 — Operators

Operators

Used to perform actions on values. Know all types and especially the difference between == and ===.

javascript — all operator types
// 1. Arithmetic
let a = 10, b = 3;
a + b   // 13  Addition
a - b   // 7   Subtraction
a * b   // 30  Multiplication
a / b   // 3.33 Division
a % b   // 1   Modulus (remainder)
a ** b  // 1000 Exponentiation (a^b)
a++      // Post-increment (returns a, then increments)
++a      // Pre-increment (increments, then returns a)

// 2. Comparison
10 == "10"   // true  — loose equality (type coercion)
10 === "10"  // false — strict equality (no coercion)
10 != "10"   // false
10 !== "10"  // true
10 > 5        // true
10 < 5        // false

// 3. Logical
true && false  // false (AND — both must be true)
true || false  // true  (OR — at least one true)
!true          // false (NOT)

// 4. Ternary operator — shorthand if/else
let result = (2 + 3 === 5) ? "yes" : "no";  // "yes"

// 5. Nullish Coalescing (??) — returns right side if left is null/undefined
let val = null ?? "default";               // "default"

// 6. Optional Chaining (?.) — safely access nested properties
let user = null;
console.log(user?.name);                  // undefined (no error)
💡 Always use === (strict equality) in JS. == does type coercion which causes unexpected results: 0 == false is true, "" == false is true.

08 — Loops

Loops

Repeat a block of code — know all loop types and when to use each.

javascript — for, while, do-while, for...of, for...in
// for loop — when you know the count
for (let i = 0; i < 5; i++) {
  console.log(i);
}

// while loop — when condition-driven
let i = 0;
while (i < 5) {
  console.log(i);
  i++;
}

// do...while — runs at least once
let n = 0;
do {
  console.log(n);
  n++;
} while (n < 3);

// for...of — iterate over array values
let fruits = ["apple", "banana", "cherry"];
for (let fruit of fruits) {
  console.log(fruit);
}

// for...in — iterate over object keys
let student = { name: "Alice", age: 20 };
for (let key in student) {
  console.log(key, student[key]);
}

// break — stop loop completely
for (let i = 0; i <= 5; i++) {
  if (i === 3) break;          // stops at 3
  console.log(i);
}

// continue — skip current iteration
for (let i = 0; i <= 5; i++) {
  if (i === 3) continue;       // skips 3, continues loop
  console.log(i);
}

10 — this Keyword

this Keyword

The this keyword refers to the object that is currently calling the function — its value depends on context.

javascript — this in different contexts
// In an object method — this = the object
const user = {
  name: "Balaji",
  show: function() {
    console.log(this.name);         // "Balaji"
  }
};
user.show();

// Arrow function — this = surrounding (lexical) scope
const obj = {
  name: "Alice",
  show: () => {
    console.log(this.name);         // undefined — no own this
  }
};

// In global context — this = window (browser)
console.log(this);                   // Window object in browser

// In a class — this = the instance
class Person {
  constructor(name) { this.name = name; }
  greet() { console.log(this.name); }
}
new Person("Bob").greet();           // "Bob"
11 — Closures

Closures

A closure is when an inner function remembers variables from its outer function even after the outer function has finished running.

💡 Closures are created every time a function is created in JavaScript. They give inner functions access to the outer function's scope.
javascript — closure example
function outer() {
  let count = 0;               // outer variable

  function inner() {
    count++;
    console.log(count);
  }
  return inner;
}

const demo = outer();            // outer() finishes, but count is remembered
demo();                          // 1
demo();                          // 2
demo();                          // 3
javascript — practical closure uses
// 1. Private data (data encapsulation)
function createCounter() {
  let count = 0;                 // private — not accessible outside
  return {
    increment: () => ++count,
    decrement: () => --count,
    getCount:  () => count
  };
}
const counter = createCounter();
counter.increment();
console.log(counter.getCount());  // 1

// 2. Memoization — remember previous results
function memoize(fn) {
  let cache = {};
  return function(n) {
    if (cache[n]) return cache[n];
    cache[n] = fn(n);
    return cache[n];
  };
}
Uses of Closures
  • Data privacy — hide internal variables (like private fields)
  • Maintaining state — remember values between function calls
  • Factory functions — create multiple instances with private data
  • Memoization — cache results to improve performance
  • Event handlers — retain access to variables from when handler was created
12 — call, apply, bind

call(), apply(), bind()

Three methods to explicitly set the value of this for a function call.

javascript — call, apply, bind
const person = { name: "Alice" };

function greet(city, country) {
  console.log(`${this.name} from ${city}, ${country}`);
}

// call() — invoke immediately, args passed one by one
greet.call(person, "Chennai", "India");
// Output: Alice from Chennai, India

// apply() — invoke immediately, args passed as array
greet.apply(person, ["Mumbai", "India"]);
// Output: Alice from Mumbai, India

// bind() — returns NEW function with fixed this (does NOT call immediately)
const boundGreet = greet.bind(person, "Delhi");
boundGreet("India");
// Output: Alice from Delhi, India

13 — Currying

Currying

Converting a function with multiple arguments into a sequence of nested functions, each taking one argument at a time.

javascript — currying
// Normal function
function add(a, b) { return a + b; }
add(2, 3);              // 5

// Curried version
function curriedAdd(a) {
  return function(b) {
    return a + b;
  };
}
console.log(curriedAdd(2)(3));   // 5

// Arrow function curried version
const multiply = a => b => a * b;
console.log(multiply(3)(4));     // 12

// Practical use: pre-set one argument
const double = multiply(2);      // pre-set a = 2
console.log(double(5));           // 10
console.log(double(7));           // 14
14 — Pure vs Impure Functions

Pure vs Impure Functions

A core concept in functional programming — important for writing predictable, testable code.

Pure Function predictable
  • Always returns the same output for the same input
  • Does not change anything outside the function (no side effects)
  • Easy to test, debug, and reason about
python
function add(a, b) { return a + b; }
add(2, 3);   // always 5
Impure Function side effects
  • Changes something outside the function (modifies global state)
  • Or gives different outputs for the same inputs
  • Examples: console.log(), Math.random(), Date.now(), DOM changes
javascript
let count = 0;
function increase() {
  count++;               // modifies outside
  return count;
}

17 — Spread & Rest

Spread Operator & Rest Operator

Both use ... but in opposite directions — spread expands, rest collects.

javascript — spread vs rest
// SPREAD — expands array/object into individual elements

// Copy and merge arrays
const arr1 = [10, 20, 30];
const arr2 = [...arr1, 40, 50];
console.log(arr2);                  // [10, 20, 30, 40, 50]

// Copy and extend objects
const person1 = { name: "Balaji" };
const person2 = { ...person1, email: "b@gmail.com" };
console.log(person2);              // { name: "Balaji", email: "b@gmail.com" }

// Spread into function arguments
const nums = [3, 1, 4, 1, 5];
console.log(Math.max(...nums));    // 5

// REST — collects multiple values into an array
function sum(...numbers) {          // rest parameter
  return numbers.reduce((a, b) => a + b, 0);
}
console.log(sum(1, 2, 3, 4));       // 10
console.log(sum(10, 20));             // 30

19 — Async JavaScript

Synchronous vs Asynchronous

JavaScript is single-threaded — it can only do one thing at a time. Async allows long tasks to run in the background without blocking other code.

Synchronous blocking
  • Code executes line by line, in order
  • Each line waits for the previous one to finish
  • If one task is slow → everything waits
Asynchronous non-blocking
  • Long tasks (API calls, timers) run in the background
  • JS continues to the next line without waiting
  • Results are handled via callbacks, promises, or async/await
javascript — sync vs async output order
// Synchronous — runs in order
console.log("first");
console.log("second");
console.log("third");
// Output: first, second, third

// Asynchronous — setTimeout deferred to task queue
console.log("first");
console.log("second");
setTimeout(() => console.log("third"), 3000);
console.log("fourth");
console.log("fifth");
// Output: first, second, fourth, fifth, (3s delay) third
20 — Callbacks & HOF

Callbacks & Higher-Order Functions

Callbacks are the foundation of async JS — a function passed as an argument to another function.

javascript — callbacks and callback hell
// Simple callback
setTimeout(() => {
  console.log("This runs after 2 seconds");
}, 2000);

// Higher-Order Function — takes a function as argument
const register = (callback) => {
  setTimeout(() => {
    console.log("Registered!");
    callback();
  }, 2000);
};
const login = () => console.log("Logged in!");
register(login);

// Callback Hell — deeply nested, hard to maintain
getData((data) => {
  processData(data, (processed) => {
    saveData(processed, (result) => {
      sendEmail(result, () => {
        console.log("Done!");  // pyramid of doom
      });
    });
  });
});
⚠ Callback Hell = deeply nested callbacks that are hard to read, debug, and maintain. This is why Promises and async/await were introduced.
21 — Promises

Promises

A Promise represents the eventual completion or failure of an asynchronous operation — eliminates callback hell.

javascript — promise chain
const register = () => new Promise((resolve, reject) => {
  setTimeout(() => {
    console.log("register");
    resolve("register-success");
  }, 2000);

const login = () => new Promise((resolve, reject) => {
  setTimeout(() => {
    console.log("login");
    resolve();
  }, 1000);

// Promise chaining — cleaner than nested callbacks
register()
  .then(login)
  .then(() => console.log("All done!"))
  .catch((error) => console.log("Error:", error));

// Promise.all — run multiple promises in parallel
Promise.all([promise1, promise2])
  .then(([r1, r2]) => console.log(r1, r2));   // waits for ALL

// Promise.race — resolves with first settled promise
Promise.race([promise1, promise2])
  .then((winner) => console.log(winner));

// Promise.allSettled — waits for all, regardless of success/fail
Promise.allSettled([p1, p2]).then(console.log);

23 — Event Loop

Event Loop

The mechanism that allows JavaScript to be non-blocking despite being single-threaded.

Call Stack
→
Web APIs
→
Task Queue
→
Event Loop checks stack
→
Push to Call Stack
How it works
  • Call Stack: where synchronous code runs — LIFO (Last In, First Out)
  • Web APIs: browser handles async tasks (setTimeout, fetch, event listeners) outside JS thread
  • Callback Queue (Task Queue): completed async callbacks wait here
  • Microtask Queue: Promise callbacks (.then/.catch) go here — higher priority than task queue
  • Event Loop: continuously checks if call stack is empty; if yes, pushes from microtask queue first, then task queue
javascript — event loop execution order
console.log("1 — synchronous");

setTimeout(() => console.log("2 — setTimeout"), 0);

Promise.resolve().then(() => console.log("3 — Promise"));

console.log("4 — synchronous");

// Output order:
// 1 — synchronous
// 4 — synchronous
// 3 — Promise      (microtask queue runs before task queue)
// 2 — setTimeout   (task queue)
24 — Array Methods

25 — map, filter, reduce

map(), filter(), reduce(), forEach()

The most-used array higher-order functions — know them all deeply, including reduce.

javascript — map, filter, reduce, forEach
let arr = [1, 2, 3, 4, 5, 6, 7, 8];

// map() — transforms each element, returns NEW array (same length)
let tripled = arr.map(n => n * 3);
console.log(tripled);              // [3,6,9,12,15,18,21,24]

// filter() — keeps elements that pass a test, returns NEW array
let evens = arr.filter(n => n % 2 === 0);
console.log(evens);               // [2,4,6,8]

// reduce() — combines all values into a SINGLE value
let total = arr.reduce((sum, n) => sum + n, 0);
console.log(total);               // 36

// reduce() to find max value
let max = arr.reduce((m, n) => n > m ? n : m, 0);

// reduce() to count occurrences
let words = ["a", "b", "a", "c", "b", "a"];
let count = words.reduce((acc, word) => {
  acc[word] = (acc[word] || 0) + 1;
  return acc;
}, {});                             // { a: 3, b: 2, c: 1 }

// forEach() — loop through each element (no return value)
arr.forEach(n => console.log(n));

29 — Bubbling & Capturing

Event Bubbling & Capturing

When an event occurs, it travels through the DOM in two phases — capturing (down) and bubbling (up).

Capturing: Window → Document → Body → Parent → Child
Bubbling: Child → Parent → Body → Document → Window
javascript — bubbling vs capturing
// Default (bubbling) — false = event moves up from child to parent
document.getElementById("child").addEventListener("click", () => {
  console.log("Child clicked");
});                                          // 3rd param: false (default)

document.getElementById("parent").addEventListener("click", () => {
  console.log("Parent also fires");        // bubbles up to parent
});

// Capturing — true = fires from parent DOWN to child
document.getElementById("parent").addEventListener("click", () => {
  console.log("Parent fires FIRST");
}, true);                                   // 3rd param: true = capturing

// Stop event from bubbling up
child.addEventListener("click", (e) => {
  e.stopPropagation();                      // stops bubbling
});

Prototype & Prototypal Inheritance

Every JavaScript object has a hidden link to another object called its prototype — the foundation of inheritance in JS.

javascript — prototype chain & classes

// ES6 Classes — syntactic sugar over prototype inheritance

  constructor(name) { this.name = name; }
  speak() { console.log(`${this.name} makes a sound`); }
}

class Dog extends Animal {   // inherits from Animal
  speak() {                  // override parent method
    console.log(`${this.name} barks`);

    super.speak();             // call parent method
    console.log("Fetching!");
  }
}

const dog = new Dog("Rex");
dog.speak();                  // Rex barks
dog.fetch();                  // Rex makes a sound → Fetching!

// Static methods — called on class, not instance

36 — Interview Questions

Hot Interview Questions

The most commonly asked JavaScript interview questions — review before every interview.

Q: What is the difference between == and ===?
  • == (loose equality): compares values with type coercion — 0 == false is true
  • === (strict equality): compares values AND types — 0 === false is false
  • Always use === in production code to avoid subtle bugs
Q: What is the difference between var, let, and const?
  • var: function-scoped, hoisted with undefined, can be re-declared — avoid in modern JS
  • let: block-scoped, in TDZ until declaration, cannot re-declare
  • const: block-scoped, cannot be reassigned — but objects/arrays can be mutated
Q: What is a closure? Give a real use case.
  • An inner function that remembers variables from its outer function even after the outer has finished
  • Use case: data privacy — creating private variables; memoization; event handlers retaining state
Q: What is hoisting?
  • JS moves declarations to the top of their scope during compilation (memory creation phase)
  • var is hoisted and initialised as undefined
  • let/const are hoisted but NOT initialised (Temporal Dead Zone — accessing throws ReferenceError)
  • Function declarations are fully hoisted; function expressions are not
Q: What is the event loop?
  • Mechanism that makes JS non-blocking despite being single-threaded
  • Call stack → Web APIs (async) → Task Queue → Microtask Queue → Event Loop pushes to stack when empty
  • Microtasks (Promises) run before macrotasks (setTimeout)
Q: What is the difference between Promise and async/await?
  • Both handle async operations; async/await is syntactic sugar over Promises
  • Promises use .then()/.catch(); async/await uses try/catch
  • async/await makes code look synchronous — easier to read and debug in complex flows
Q: What is the difference between call(), apply(), and bind()?
  • All three set the value of this for a function
  • call(): invokes immediately; args passed one by one
  • apply(): invokes immediately; args passed as array
  • bind(): does NOT invoke; returns a new function with fixed this
Q: What is event bubbling and how do you stop it?
  • Event bubbling: when an event on a child element also fires on all parent elements up the DOM tree
  • Stop with event.stopPropagation()
  • Prevent default browser behaviour with event.preventDefault()
Q: What is the difference between map(), filter(), and reduce()?
  • map(): transforms each element → returns new array of same length
  • filter(): keeps elements that pass a test → returns shorter new array
  • reduce(): combines all elements into a single value (sum, count, group)
Q: What is currying?
  • Converting a multi-argument function into a sequence of single-argument functions
  • add(a)(b) instead of add(a, b)
  • Useful for partial application — pre-set some arguments and reuse the function
Q: Is JavaScript single-threaded?
  • Yes — JS has a single call stack; it executes one task at a time
  • But it appears concurrent using the event loop, Web APIs (browser handles timers/fetch), and task queues
  • Web Workers allow true parallelism but with no DOM access
Q: What is the difference between localStorage and sessionStorage?
  • localStorage: data persists until manually deleted; shared across all tabs
  • sessionStorage: data only lives for the current browser tab session; cleared when tab closes
✅ Pro tip: In JS interviews, always mention real-world examples. For closures → "I used closures to create private counters." For Promises → "I used async/await with fetch to call REST APIs." Concrete examples make abstract answers memorable and show real experience.
